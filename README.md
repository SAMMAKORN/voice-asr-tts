# คุยกับ AI ด้วยเสียงแบบเรียลไทม์ (ไทย)

พูดเข้าไมค์ → ถอดเสียง (ASR) → คุยกับ LLM แบบสตรีม → อ่านออกเสียงกลับ (TTS)
พร้อม **caption บทสนทนาบนหน้าจอทันที**, **พูดแทรก AI ได้ตลอดเวลา (barge-in)**,
**ค้นอินเทอร์เน็ตเองเพื่อตอบเรื่องปัจจุบันพร้อมบอกแหล่งที่มา**
และ **บันทึกบทสนทนาทุกครั้งลง `logs/`**

ใช้ได้ **2 หน้าตา** บนแกนหลักตัวเดียวกัน:

| โหมด                                   | สั่งรัน                 | เหมาะกับ                                                          |
| -------------------------------------- | ----------------------- | ----------------------------------------------------------------- |
| 🌐 **เว็บ** (ธีม sci-fi + คู่มือในตัว) | `python3 -m web.server` | ใช้งานปกติ · มีมิเตอร์เสียง ปุ่มควบคุม และ onboarding สอนทีละขั้น |
| ⌨️ **เทอร์มินัล**                      | `python3 voice_chat.py` | ไม่อยากเปิดเบราว์เซอร์ · ต่อเข้าสคริปต์อื่น                       |

ค่า API และชื่อโมเดลทั้งหมดอ่านจาก `.env` ไม่มี hard-code ในโค้ด

---

## 🌐 โหมดเว็บ (แนะนำสำหรับผู้เริ่มใช้)

```bash
cd /voice-asr-tts
python3 -m venv .venv && source .venv/bin/activate    # ทำครั้งเดียว
pip install -r requirements.txt                       # ทำครั้งเดียว

python3 -m web.server                                 # แล้วเปิด http://127.0.0.1:8000
```

ครั้งแรกที่เปิดหน้าเว็บจะมี **คู่มือเริ่มต้น 5 ขั้น** ขึ้นมาพาทำทีละอย่าง

1. อธิบายว่าระบบทำงานยังไง (แผนภาพ MIC → ASR → LLM → TTS → ลำโพง)
2. กดขออนุญาตไมโครโฟน พร้อมมิเตอร์ให้ลองพูดดูว่าไมค์ติดจริง
3. กดตรวจระบบ — ยิงทดสอบ TTS → ASR → LLM จริงแล้วโชว์ผลทีละขั้นพร้อมเวลาที่ใช้
4. สอนวิธีคุย (ไม่มีปุ่มกดพูด แค่พูดออกมา)
5. สอนพูดแทรกและปุ่มควบคุมทุกปุ่ม → กด "เริ่มใช้งาน" แล้วคุยได้เลย

เปิดคู่มือซ้ำได้ทุกเมื่อจากปุ่ม **? วิธีใช้** มุมล่างขวา

**สิ่งที่เห็นบนหน้าเว็บ**

| ส่วน    | ทำอะไร                                                                                                                     |
| ------- | -------------------------------------------------------------------------------------------------------------------------- |
| กลางจอ  | บทสนทนาแบบสตรีมทีละคำ ติดป้าย `ถูกพูดขัด` ให้เมื่อ AI ถูกพูดแทรก                                                           |
| แผงขวา  | มิเตอร์เสียงเข้าพร้อมเส้นเกณฑ์ VAD, รูปคลื่นเสียงสด, latency ของ ASR / token แรก / TTS, จำนวนครั้งที่พูดแทรก และบันทึกระบบ |
| แถบล่าง | วงไมค์ที่เปลี่ยนสีตามสถานะ (ฟัง / คิด / พูด) · ปุ่มหยุด ปิดเสียง โหมดหูฟัง ล้างประวัติ · ช่องพิมพ์แทนการพูด                |

> ปุ่ม **🎧 หูฟัง** — ปกติปิดไว้เพราะเบราว์เซอร์มีระบบตัดเสียงสะท้อน (AEC) ให้แล้ว
> เปิดเมื่อใช้ลำโพงดังมากแล้วไมค์ยังได้ยินเสียง AI ตัวเองจนพูดแทรกตัวเอง

> เปิดจากเครื่องอื่นในวง LAN ใช้ `python3 -m web.server --host 0.0.0.0` ได้
> แต่เบราว์เซอร์จะให้สิทธิ์ไมค์เฉพาะ `localhost` หรือเว็บที่เป็น HTTPS เท่านั้น

## ⌨️ โหมดเทอร์มินัล — เริ่มใช้งานแบบเร็ว (3 ขั้นตอน)

```bash
cd /voice-asr-tts

# 1) สร้าง virtual environment แยกจาก python ของเครื่อง (ทำครั้งเดียว)
python3 -m venv .venv
source .venv/bin/activate          # ทุกครั้งที่เปิด terminal ใหม่ต้อง activate ก่อน

# 2) ติดตั้งไลบรารีที่ต้องใช้ (ทำครั้งเดียว ตอนอยู่ใน venv)
pip install -r requirements.txt

# 3) ลองรันแบบไม่ใช้ไมค์ ดูว่า API เชื่อมได้จริง
python3 voice_chat.py --selftest

# 4) เริ่มคุยด้วยเสียงจริง (แนะนำใส่หูฟังกันเสียงสะท้อน)
python3 voice_chat.py --headphones
```

> ครั้งต่อ ๆ ไปไม่ต้องสร้าง venv ใหม่ แค่ `source .venv/bin/activate` แล้วรัน
> `python3 voice_chat.py ...` ได้เลย ออกจาก venv ด้วยคำสั่ง `deactivate`

พอรันขั้นตอน 3 แล้ว โปรแกรมจะ:

1. ขอสิทธิ์ไมโครโฟน (ครั้งแรกที่ macOS จะเด้ง pop-up ให้กด "อนุญาต")
2. วัดเสียงรบกวนรอบข้างสั้น ๆ (อยู่เงียบ ๆ ~1 วินาที)
3. AI ทักทายด้วยเสียงว่า "สวัสดีครับ ผมพร้อมคุยแล้ว..."
4. หลังจากนั้น**พูดใส่ไมค์ได้เลยทันที** ไม่ต้องกดปุ่มใด ๆ — พูดจบ AI จะตอบเป็นเสียงกลับ
   พร้อมขึ้น caption บนหน้าจอ และ**พูดแทรก AI ได้ตลอดเวลา**แม้ตอนมันกำลังพูดอยู่

จบการคุยกด `Ctrl+C` หรือพิมพ์ `/quit` แล้ว Enter — บทสนทนาจะถูกบันทึกไว้ที่ `logs/` โดยอัตโนมัติ

> ถ้าไม่มีไมค์/ลำโพงตอนนี้ หรืออยากลองแบบพิมพ์ก่อน ใช้
> `python3 voice_chat.py --no-mic` แล้วพิมพ์ข้อความ+Enter แทนการพูดได้เลย

## 1. ติดตั้ง

```bash
python3 -m venv .venv          # สร้าง venv (ทำครั้งเดียว)
source .venv/bin/activate      # เข้าใช้งาน venv (ทำทุกครั้งที่เปิด terminal ใหม่)
pip install -r requirements.txt
```

macOS ต้องอนุญาตให้แอปเทอร์มินัลเข้าถึงไมโครโฟน
(System Settings → Privacy & Security → Microphone) ครั้งแรกที่รันจะมี pop-up ขึ้นมา

**ถ้าพูดแล้วเหมือนเสียงไม่เข้าเลย** ให้เช็คด้วยมิเตอร์ก่อน — สาเหตุที่พบบ่อยที่สุด
ไม่ใช่ permission แต่เป็น input volume ของเครื่องถูกหรี่ไว้ (ระบบไม่แจ้งอะไรเลย
เสียงพูดจะเข้ามาต่ำกว่าเกณฑ์ VAD ตลอด) ฝั่งเบราว์เซอร์ไม่เจอปัญหานี้เพราะมี
`autoGainControl` ชดเชยให้เอง

```bash
python3 voice_chat.py --mic-check     # มิเตอร์สด บอกระดับเสียง เกณฑ์ และ input volume
osascript -e 'set volume input volume 80'     # แก้ที่ต้นเหตุบน macOS
```

ตอนเริ่มโปรแกรมจะวัดเสียงรบกวนแล้ว**ขยายเสียงไมค์ให้อัตโนมัติ** (`MIC_GAIN=0`)
ถ้าอยากคุมเอง ใส่ตัวเลขใน `.env` หรือ `--mic-gain 4`

## 2. ตรวจว่าพร้อมใช้งาน (ไม่ใช้ไมค์)

```bash
python3 voice_chat.py --selftest     # ทดสอบ TTS → ASR → LLM ครบวง
python3 tests/test_offline.py        # ตรรกะ VAD / การพูดแทรก / การตัดประโยค (ไม่ต่อเน็ต)
python3 tests/test_web.py            # สะพานฝั่งเว็บ WebMic/WebSpeaker/WebConsole (ไม่ต่อเน็ต)
python3 tests/test_search.py         # ค้นเน็ต + tool calling  (--offline = ทดสอบเฉพาะส่วนที่ไม่ต่อเน็ต)
python3 tests/test_web_e2e.py        # เปิดเซิร์ฟเวอร์จริงแล้วจำลอง WebSocket คุยครบวง (~30 วินาที)
python3 tests/test_browser.py        # เบราว์เซอร์จริงด้วย Playwright (~2 นาที)
```

### ทดสอบด้วยเบราว์เซอร์จริง

`tests/test_browser.py` เปิด Chromium จริงผ่าน Playwright แล้วใช้**ไมโครโฟนปลอม
ที่ป้อนเสียงจากไฟล์ WAV** จึงทดสอบเส้นทางเสียงได้ทั้งเส้นโดยไม่ต้องมีคนพูด

```bash
pip install playwright && python3 -m playwright install chromium   # ทำครั้งเดียว
python3 tests/test_browser.py            # headless
python3 tests/test_browser.py --headed   # เปิดหน้าต่างให้ดูด้วยตา
```

สคริปต์จะสร้างไฟล์เสียงเองด้วย TTS (คำถามที่วินาทีที่ 9, เสียงพูดแทรกที่วินาทีที่ 21)
แล้วตรวจ 43 ข้อ ครอบคลุมคู่มือทั้ง 5 ขั้น, `getUserMedia` + AudioWorklet,
การถอดเสียงจริง, การเล่นเสียงจนจบก้อน, การตัดเสียงกลางคันตอนถูกพูดแทรก,
การค้นเน็ตพร้อมแสดงแหล่งที่มา, ปุ่มควบคุมทุกปุ่ม และต้องไม่มี error ใน console เลย

## 3. เริ่มคุย

```bash
python3 voice_chat.py                # ใช้ลำโพง (มีระบบกันเสียงลำโพงย้อนเข้าไมค์)
python3 voice_chat.py --headphones   # ใส่หูฟัง → พูดแทรกไวขึ้นชัดเจน (แนะนำ)
```

ระหว่างคุย:

| ทำอะไร                 | ผลลัพธ์                                             |
| ---------------------- | --------------------------------------------------- |
| พูดขณะ AI กำลังพูด     | AI หยุดกลางประโยคทันที แล้วฟังคุณ                   |
| กด `Enter`             | สั่งหยุด AI ด้วยมือ                                 |
| พิมพ์ข้อความ + `Enter` | ส่งข้อความแบบไม่ใช้เสียง (ใช้ตอนอยู่ที่เงียบไม่ได้) |
| `/mute`                | ปิด/เปิดเสียงพูดของ AI                              |
| `/clear`               | ล้างประวัติการสนทนา                                 |
| `/log`                 | บอกที่เก็บบันทึก                                    |
| `/quit` หรือ `Ctrl+C`  | ออก                                                 |

### ตัวเลือกอื่น

```
--list-devices          ดูรายการไมค์/ลำโพงพร้อมหมายเลข
--input-device 0        เลือกไมค์
--output-device 1       เลือกลำโพง
--model claude-opus-5   ทับค่า CHAT_MODEL
--no-tts                แสดง caption เฉย ๆ ไม่ออกเสียง
--no-mic                โหมดพิมพ์อย่างเดียว
--no-web                ปิดการค้นเน็ต ตอบจากความรู้ในโมเดลอย่างเดียว
--save-audio            เก็บไฟล์เสียงที่เราพูดไว้ตรวจย้อนหลัง
--threshold 0.02        ยกเกณฑ์เสียงพูด (ที่เสียงดัง/ไมค์ไว)
--mic-check             มิเตอร์เสียงเข้าแบบสด ใช้ตอนพูดแล้วเสียงไม่เข้า
--mic-gain 4            คุมอัตราขยายเสียงไมค์เอง (ไม่ใส่ = คำนวณอัตโนมัติ)
--one-voice             รอคำตอบจบแล้วพูดทีเดียว เสียงคนเดียวกันแต่เริ่มพูดช้าลง
```

## 4. บันทึกการสนทนา

ทุกครั้งที่รันจะได้โฟลเดอร์ `logs/session-YYYYMMDD-HHMMSS/`

| ไฟล์                 | เนื้อหา                                                                                  |
| -------------------- | ---------------------------------------------------------------------------------------- |
| `transcript.md`      | บทสนทนาอ่านง่าย มีเวลากำกับ และระบุจุดที่ AI ถูกพูดขัด                                   |
| `session.jsonl`      | ทุกเหตุการณ์: `asr`, `message`, `tts`, `interrupt`, `tool` (การค้นเน็ต), latency ทุกขั้น |
| `audio/user-NNN.wav` | เสียงที่ผู้ใช้พูด (เฉพาะเมื่อใส่ `--save-audio`)                                         |

ดู latency ย้อนหลังได้ เช่น

```bash
python3 -c "import json,sys;[print(r.get('type'),r.get('latency_ms') or r.get('first_token_ms')) for r in map(json.loads,open(sys.argv[1]))]" logs/session-*/session.jsonl
```

## 5. ค้นข้อมูลจากอินเทอร์เน็ต

AI ค้นเน็ตเองได้เมื่อถูกถามเรื่องที่เปลี่ยนตามเวลา แล้ว**บอกแหล่งที่มาให้เห็นทุกครั้ง**
ใช้ DuckDuckGo จึงไม่ต้องสมัคร API key และไม่มีค่าใช้จ่ายเพิ่ม

```
คุณ:  ราคาทองคำแท่งวันนี้รับซื้อบาทละเท่าไหร่
      🔎 กำลังค้นข้อมูล: ราคาทองคำแท่งวันนี้ รับซื้อ        ← AI พูดคั่นว่า "ขอค้นข้อมูลสักครู่นะครับ"
AI:   อ้างอิงจากสมาคมค้าทองคำ วันนี้ราคาทองคำแท่งรับซื้อบาทละ 68,500 บาทครับ
      🔎 แหล่งที่มา
         1. aagold-th.com   2. goldzaa.com   3. ทองคําราคา.com
```

**เครื่องมือที่ AI เรียกได้**

| เครื่องมือ   | ทำอะไร                                                              |
| ------------ | ------------------------------------------------------------------- |
| `web_search` | ค้นแล้วได้หัวข้อ + ลิงก์ + คำอธิบายย่อ 5 อันดับแรก (ตัดโดเมนซ้ำออก) |
| `open_page`  | เปิดอ่านเนื้อหาหน้าเว็บเมื่อคำอธิบายย่อยังไม่พอตอบ                  |

**แหล่งที่มาแสดงที่ไหนบ้าง** — บนหน้าเว็บขึ้นเป็นชิปลิงก์ใต้คำตอบ (กดเปิดได้),
บนเทอร์มินัลพิมพ์เป็นรายการใต้คำตอบ, และเก็บลง `transcript.md` เป็นลิงก์ Markdown
กับ `session.jsonl` ครบทุกครั้ง

**ข้อควรรู้**

- ระบบใส่**วันเวลาปัจจุบัน**ให้โมเดลทุกครั้ง ไม่งั้นมันไม่รู้ว่า "วันนี้" คือวันไหน
- ลำดับใน system prompt สำคัญมาก — กติกาเรื่องเครื่องมือต้องอยู่**บนสุด**
  ถ้าเอาไปต่อท้ายบุคลิก โมเดลจะมองข้ามแล้วเดาตัวเลขเอง (ทดสอบแล้วเป็นแบบนั้นจริง)
- รอบสุดท้ายของการเรียกเครื่องมือยังต้องแนบสคีมา `tools` ไปด้วยเสมอ แล้วใช้
  `tool_choice: "none"` ห้ามเรียกเพิ่มแทน — ถ้าตัด `tools` ทิ้ง โมเดลจะอ่านประวัติ
  `tool_calls` ในบทสนทนาไม่ออกแล้วตอบกลับมาเป็นค่าว่างเป็นครั้งคราว
- ถ้าค้นแล้วยังไม่ได้ข้อความกลับมาจริง ๆ ระบบจะกระทุ้งซ้ำอีกครั้ง และถ้ายังไม่ได้อีก
  จะพูดขอโทษแทนการปล่อยเงียบใส่ผู้ใช้
- คำถามความรู้ทั่วไปที่ไม่เปลี่ยนตามเวลาจะไม่ค้น เพื่อไม่ให้ตอบช้าโดยไม่จำเป็น
- `open_page` เปิดได้เฉพาะ http/https ที่เป็นที่อยู่สาธารณะ — บล็อก localhost
  และ IP วงในเพื่อกันการยิงเข้าเครือข่ายภายใน
- ปิดได้ด้วย `--no-web` หรือ `WEB_SEARCH=0` ใน `.env`

การจัดคิว TTS การตัดสินใจพูดแทรก และการบันทึก log เป็นโค้ดชุดเดียวกัน
แก้ที่เดียวจึงมีผลทั้งสองโหมด

## 7. หลักการทำงาน (สรุปสั้น)

**พูดแทรกได้จริง** — ไมค์อัดตลอดเวลาแยกเธรด ไม่เคยปิดแม้ตอน AI พูด
เมื่อจับได้ว่าเริ่มมีเสียงพูด (`VAD_CONFIRM_MS_PLAYBACK` = 340 ms ขณะ AI พูด) จะ

1. หยุดลำโพงทันที (ล้างบัฟเฟอร์ที่ค้างอยู่)
2. ล้างคิว TTS ที่รอสังเคราะห์
3. ตัดการอ่านสตรีมจาก LLM ทิ้ง
4. บันทึกคำตอบที่โมเดลเขียนไว้ลง history **ทั้งข้อความ** ต่อท้ายด้วยหมายเหตุว่าถูกขัด
   ตรงไหน เพื่อให้ AI รู้ว่าพูดค้างไว้แค่ไหนแต่ยังจำเนื้อหาที่ตอบไปแล้วได้

**ยืนยันก่อนว่าเป็นคนพูดจริง** — VAD ตัดสินจากระดับเสียงอย่างเดียว เสียงลำโพงที่รั่ว
เข้าไมค์เป็นช่วงสั้น ๆ จึงหลุดมาเป็น "การพูดแทรก" ได้ พอส่งเข้า ASR โมเดลก็เดา
ออกมาเป็นข้อความมั่ว ๆ มักเป็นภาษาอื่นและสั้น (เจอจริงในบันทึก: `啥东西？`,
`我爱你。`, `bản thân cậu.`) ผลคือคำตอบจริงถูกทิ้งและ history ถูกยัดขยะจนโมเดล
ตามเรื่องไม่ทัน ระบบจึงเช็คผล ASR ก่อน ถ้าสั้นเกิน `BARGE_IN_MIN_CHARS` หรือ
ไม่มีอักษรไทยเลยทั้งที่ตั้ง `LANG_HINT=th` จะถือว่าเป็นเสียงสะท้อน แล้ว
**คืนคำตอบเดิมกลับเข้า history** พร้อมบันทึก event `false_barge_in` ไว้ตรวจย้อนหลัง

**จำผลค้นเว็บข้ามเทิร์นได้** — ผลจาก `web_search` / `open_page` ถูกเก็บไว้
(`KEEP_FINDINGS` ชุดล่าสุด) แล้วแนบกลับไปเป็นข้อความ system ทุกครั้งที่ถามต่อ
ไม่ได้เก็บเป็น `role=tool` เพราะการตัดประวัติอาจตัดจนเหลือ tool ที่ไม่มี
`tool_calls` คู่กัน แล้ว API จะปฏิเสธทั้งคำขอ

**กันไมค์ได้ยินเสียงตัวเอง** — ขณะเล่นเสียง ระบบประเมินอัตราที่เสียงลำโพงรั่วเข้าไมค์
(`leak`) แบบปรับตัวอัตโนมัติ แล้วยกเกณฑ์เป็น `leak × ความดังลำโพง × ECHO_MARGIN`
เสียงคนพูดจริงจะดังทะลุเกณฑ์ ส่วนเสียงสะท้อนของตัวเองไม่ทะลุ
ถ้าใส่หูฟังให้ใช้ `--headphones` เพื่อปิดกลไกนี้ (ตอบสนองไวสุด ~120 ms)

**พูดไปพร้อมกับที่ข้อความกำลังไหล** — ระบบไม่รอให้ LLM ตอบจบ พอได้ข้อความก้อนแรก
(~24 ตัวอักษร) ก็ส่ง TTS ทันที แล้วสังเคราะห์ก้อนถัดไปคู่ขนานไปกับที่ก้อนก่อนกำลังเล่น
วัดจริงกับคำตอบ ~400 ตัวอักษร: **เริ่มพูดหลังพิมพ์จบ 4.7 วินาที** เทียบกับ 12.8 วินาที
ถ้ารอคำตอบครบก่อน (`--one-voice`)

ก้อนถัด ๆ ไปตั้งให้**โตขึ้นเรื่อย ๆ** (`TTS_CHUNK_GROWTH=1.8`) เพราะ OmniVoice
สุ่มเสียงผู้พูดใหม่ทุก request ยิ่งแบ่งถี่เสียงยิ่งเปลี่ยนคนบ่อย แต่โตได้แค่เท่าที่
ก้อนถัดไปยังสังเคราะห์ทันก่อนก้อนก่อนหน้าจะเล่นจบ ไม่งั้นเสียงจะขาดเป็นช่วง ๆ
วัดจริงกับคำตอบ 379 ตัวอักษร ได้ 4 ก้อนและต่อเนื่องทุกก้อน:

```
ก้อน  ตัวอักษร  สังเคราะห์  เสียงยาว
  1        39       2.3s      3.5s
  2        60       2.7s      4.8s   ← 2.7 < 3.5 จึงต่อเนื่อง
  3        98       4.3s      7.8s   ← 4.3 < 4.8
  4       179       3.8s     15.4s   ← 3.8 < 7.8
```

**ทำไมล็อกเสียงให้เป็นคนเดียวกันไม่ได้** — ทดสอบครบทุกทางแล้ว:

| ทางที่ลอง | ผล |
| --- | --- |
| ส่ง `voice` ไปกับ request | HTTP 500 — vLLM-Omni online เปิดแค่ auto voice |
| ส่ง `seed` / `speaker` / `voice_id` | รับ 200 แต่ถูกเมิน ได้เสียงต่างกันทุกครั้ง |
| สตรีมเสียงออกมาระหว่างสังเคราะห์ | ไม่รองรับ — TTFB 4.85s / total 4.99s (ลอง `pcm`/`mp3`/`opus` แล้ว) |
| เติมคำนำหน้าเดิมทุกก้อนเพื่อล็อกเสียง | ไม่ช่วย — f0 ยังได้ 162 / 170 / 130 Hz |

เสียงถูกกำหนดจาก**ตัวข้อความ** (ข้อความเดิมเรียกซ้ำได้เสียงใกล้เคียงกัน ±8 Hz
แต่คนละข้อความห่างกันได้ ~45 Hz) จึงเลี่ยงไม่ได้ว่าแบ่งกี่ก้อนก็ได้เท่านั้นเสียง
ถ้าต้องการเสียงเดียวจริง ๆ มีสองทาง: ใช้ `--one-voice` (แลกกับเริ่มพูดช้าลง
และคำตอบยาวเกิน `TTS_MAX_CHARS=260` ก็ยังต้องแบ่งอยู่ดี) หรือให้ฝั่งเซิร์ฟเวอร์
เปิด voice cloning (`ref_audio`) ซึ่ง vLLM-Omni ทำได้เฉพาะ offline inference

เวลาสังเคราะห์โตเร็วกว่าความยาวข้อความมาก จึงต้องมีเพดาน `TTS_MAX_CHARS`:

```
 77 ตัวอักษร →  2.3s      233 ตัวอักษร →  4.8s
155 ตัวอักษร →  3.3s      389 ตัวอักษร → 14.2s   ← พุ่งชัดเจน
```

**เส้นทางเสียงในโหมดเว็บ** — เบราว์เซอร์ทำหน้าที่แทนการ์ดเสียง

```
AudioWorklet → PCM 16 kHz/20ms → WebSocket (binary) → VoiceGate (VAD ตัวเดิม) → ASR
                                                                                  ↓
   ลำโพงเบราว์เซอร์ ← ต่อคิวเล่นแบบ gapless ← WebSocket ([epoch|seq|PCM]) ← TTS ← LLM
```

- ไมค์เปิดค้างตลอด ส่งขึ้นเซิร์ฟเวอร์ตลอด การตัดสินใจว่า "พูดจบ" หรือ "พูดแทรก"
  ยังทำที่ `vc/vad.py` ตัวเดิม เบราว์เซอร์ไม่ตัดสินใจเอง
- เสียงแต่ละก้อนติดหมายเลข `epoch/seq` ไปด้วย เบราว์เซอร์รายงานกลับเมื่อเล่นจบก้อนไหน
  เซิร์ฟเวอร์จึงรู้แน่ชัดว่า**ผู้ใช้ได้ยินไปถึงตรงไหน**ก่อนถูกพูดขัด แล้วบันทึกใน history
  ให้ตรงกับที่ได้ยินจริง (ถ้าเบราว์เซอร์เงียบหายไป มีเวลาหมดอายุกันค้างไว้)
- พอ VAD จับได้ว่ามีคนพูด เซิร์ฟเวอร์ส่ง `stop` ลงมา เบราว์เซอร์ยกเลิก
  `AudioBufferSourceNode` ที่จองคิวไว้ทั้งหมดทันที เสียงจึงเงียบกลางประโยคได้จริง
- การกันเสียงลำโพงย้อนเข้าไมค์ใช้ AEC ของเบราว์เซอร์ (`echoCancellation: true`)
  **ร่วมกับ** `ECHO_GUARD` ฝั่งเซิร์ฟเวอร์ เพราะจากบันทึกจริงลำโพงโน้ตบุ๊กยังรั่ว
  เข้าไมค์พอให้ ASR เดาเป็นข้อความมั่ว ๆ แล้วไปตัดคำตอบทิ้ง (เบราว์เซอร์รายงาน
  ระดับเสียงขาออกกลับมาทุก 100 ms ฝั่งเซิร์ฟเวอร์จึงประเมิน leak ได้เหมือนโหมดเทอร์มินัล)
  ถ้าใส่หูฟังให้กดปุ่มโหมดหูฟังในหน้าเว็บเพื่อปิด จะพูดแทรกได้ไวขึ้น

## 8. ค่าที่ปรับได้ใน `.env`

```
CHAT_MODEL / ASR_MODEL / TTS_MODEL   ชื่อโมเดล
CHAT_TEMPERATURE / CHAT_MAX_TOKENS   พฤติกรรม LLM (350 token — ยาวกว่านี้ TTS รอนาน)
SYSTEM_PROMPT                        บุคลิก (ค่าเริ่มต้นบังคับตอบไทย สั้น ไม่มี Markdown)
KEEP_FINDINGS                        ผลค้นเว็บย้อนหลังที่จำไว้ให้ตอบต่อได้ (4)
TTS_SINGLE_REQUEST                   0 = พูดไปพร้อมข้อความ / 1 = รอจบแล้วพูดทีเดียว
TTS_FIRST_CHARS                      ขนาดก้อนแรก ยิ่งเล็กยิ่งเริ่มพูดเร็ว (24)
TTS_CHUNK_CHARS / TTS_CHUNK_GROWTH   ขนาดก้อนถัดไปและอัตราที่โตขึ้น (60 / 1.8)
TTS_MAX_CHARS                        เพดานต่อ request — เกินนี้เวลาสังเคราะห์พุ่ง (260)
TTS_SEARCH_FILLER                    พูด "ขอค้นข้อมูลสักครู่" ระหว่างค้นเน็ตไหม
MIC_GAIN / MIC_TARGET_NOISE          ขยายเสียงไมค์ 0 = คำนวณเองจากเสียงรบกวนที่วัดได้
VAD_ABS_THRESHOLD                    ไมค์ไวเกิน → เพิ่มค่า / ไม่จับเสียง → ลดค่า
VAD_NOISE_MULT                       ตัวคูณเหนือเสียงรบกวนรอบข้าง
VAD_CONFIRM_MS(_PLAYBACK)            ต้องพูดนานเท่าไรจึงเริ่มอัด / จึงขัด AI
VAD_END_SILENCE_MS                   เงียบเท่าไรถือว่าพูดจบ (650 ms)
ECHO_GUARD / ECHO_MARGIN             ระบบกันเสียงลำโพงย้อนเข้าไมค์
BARGE_IN_MIN_CHARS                   ถอดเสียงสั้นกว่านี้ = ไม่นับว่าพูดขัดจริง
WEB_SEARCH                           เปิด/ปิดการค้นอินเทอร์เน็ต (ค่าเริ่มต้นเปิด)
SEARCH_RESULTS                       จำนวนผลค้นหาที่ส่งให้โมเดล (5)
SEARCH_TIMEOUT                       วินาทีที่ยอมรอผลค้นหา (12)
FETCH_MAX_CHARS                      ความยาวเนื้อหาหน้าเว็บสูงสุดที่ส่งให้โมเดล (3000)
TOOL_ROUNDS                          จำนวนรอบสูงสุดที่ยอมให้เรียกเครื่องมือต่อหนึ่งคำถาม (2)
```

> **หมายเหตุ TTS:** `k2-fsa/OmniVoice` บน LiteLLM proxy นี้รับได้เฉพาะ payload
> `{model, input}` — ถ้าส่ง `voice` หรือ `response_format` เพิ่มจะได้ HTTP 500
> เสียงที่คืนมาเป็น WAV 24 kHz mono
